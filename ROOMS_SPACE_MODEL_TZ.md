# FreeDom — техническое задание: интерактивная карта дома и территории

## 1. Цель

Сделать страницу **Комнаты / FreeDom Space Rooms**, которая позволяет человеку сразу понять устройство FreeDom визуально, а не читать длинный каталог.

Главный принцип: **человек сначала видит пространство, затем выбирает место, затем получает описание/фото и может перейти к бронированию.**

Существующую архитектуру сайта не менять. Это отдельная ветка **Комнаты** в уже утверждённой пятиветочной главной: Пространство / Кухня / Баня / События / Комнаты.

## 2. Визуальная концепция

Референс — выбранный вариант 4: интерактивная карта, максимально приближенная к ощущению реального пространства.

Не использовать обычную сетку карточек как основной интерфейс.

Основной экран:
- большая карта;
- слева/сверху — переключение «Дом / Территория»;
- внутри дома — этажи;
- архитектурный план должен напоминать понятный план квартиры/строительный чертёж: стены, комнаты, дверные проёмы, лестница, подписи этажей;
- территория — отдельный пространственный слой с домом, бассейном, бунгало, баней, спортом, прудом, дорожками и другими объектами;
- справа на desktop / снизу на mobile — информационная карточка выбранного объекта.

## 3. Навигация по карте

### Верхний уровень
- Дом
- Территория

### Дом
- Мансарда
- 3 этаж
- 2 этаж
- 1 этаж
- −1 этаж

При смене этажа карта не должна просто исчезать и появляться. Она должна **плавно перемещаться/перестраиваться**, сохраняя ощущение одной модели дома.

## 4. Архитектурная модель

План должен быть схематическим, но архитектурно понятным:
- наружный контур;
- внутренние стены;
- комнаты;
- коридоры;
- лестничный узел;
- балконы;
- основные двери/проёмы;
- подпись этажа;
- условные зоны общего пользования.

Важно: до получения точного строительного плана **не выдавать текущую SVG/CSS-схему за точный масштаб или размеры**. На первом этапе это UX-модель топологии. После предоставления точного плана/фотографий геометрию можно заменить, не меняя механику интерфейса.

## 5. Выбор объекта

При клике на комнату:

1. карта плавно приближается к выбранной комнате;
2. остальные зоны слегка приглушаются;
3. выбранная комната становится визуальным центром;
4. появляется информационная карточка;
5. в карточке появляется реальная фотография объекта;
6. название;
7. краткое описание;
8. вместимость;
9. режим бронирования — «по местам» или «целиком»;
10. доступность для выбранных дат;
11. цена — только из актуального источника, когда она будет подтверждена;
12. кнопка **«Забронировать»**.

Анимация должна ощущаться как **камера приближается к месту**, а не как открытие обычного modal.

## 6. Фото

Фото — отдельный media-slot и не должны определять геометрию карты.

Пока используются существующие изображения проекта как временные реальные материалы. Позже они могут быть заменены профессиональными фотографиями без изменения структуры UI.

Для каждого объекта предусмотреть:
- главное фото;
- дополнительные фото;
- возможность позже добавить короткое видео/360° без изменения карты.

## 7. Реальные объекты каталога

На момент разработки в Supabase существуют 11 записей размещения. Каталог должен оставаться источником истины через существующий `get_rooms_catalog` / `rooms-catalog.js`, а не дублироваться вручную в UI.

Известные объекты:
- Хостел эконом — 8 мест — `places`;
- Хостел стандарт — 4 места — `places`;
- Хостел стандарт №2 — 4 места — `places`;
- Семейная комната — бронируется целиком;
- Двухместный с балконом №1 — целиком;
- Двухместный с балконом №2 — целиком;
- Мансардная комната №1 — целиком;
- Мансардная комната №2 — целиком;
- Место под звёздами — целиком;
- Бунгало в саду — целиком.

Примечание: количество/география объектов на визуальной карте и количество записей каталога не обязаны совпадать 1:1. Карта описывает пространство, каталог — продаваемые объекты. Их связывает `room_id`/mapping layer.

## 8. Доступность

Не переписывать существующую booking/availability систему.

Карта должна получать только необходимую публичную информацию:
- свободно/занято;
- для хостелов — свободные места;
- для объектов whole — свободен/занят.

Персональные данные бронирований на карту не выводятся.

## 9. Информационная карточка

Desktop:
- карта занимает большую часть экрана;
- карточка фиксируется справа;
- карточка не должна перекрывать сам выбранный объект.

Mobile:
- карта остаётся главным экраном;
- после выбора появляется нижняя карточка/bottom sheet;
- пользователь может закрыть её и продолжить исследование;
- карта не должна превращаться в длинный список.

## 10. Территория

Отдельный пространственный слой.

Основные объекты текущей модели:
- дом;
- дорожка от ворот вниз;
- бассейн;
- летняя кухня;
- тренажёрная зона;
- бунгало;
- гамак;
- пруд;
- мостик;
- баня;
- будущая зона/детская площадка.

В перспективе территория должна поддерживать ту же механику: клик → приближение → фото → описание → действие.

## 11. Анимация камеры

Состояния:

`overview → floor → selected-object`

При выборе этажа:
- scale/translate карты плавно меняются;
- старый слой растворяется не мгновенно;
- новый слой появляется в той же системе координат.

При выборе комнаты:
- камера центрируется на комнате;
- масштаб увеличивается примерно в 1.6–2.2 раза в зависимости от viewport;
- карточка появляется с задержкой после начала движения камеры;
- длительность перехода ориентировочно 600–1100 ms.

При закрытии:
- камера возвращается к предыдущему масштабу и позиции;
- выбранный этаж сохраняется.

## 12. Легенда

Не перегружать карту.

Использовать минимум условных обозначений:
- 🟢 доступно;
- 🔴 занято;
- нейтральный цвет — общее пространство;
- отдельный тон — лестницы/маршруты.

## 13. Что НЕ делать

- не превращать карту в обычный Booking-каталог;
- не делать псевдо-3D ради самого 3D;
- не использовать холодный sci-fi/cyberpunk стиль;
- не добавлять лишние декоративные элементы ради эффекта;
- не ломать существующий FreeDom Space;
- не переписывать backend ради дизайна;
- не фиксировать геометрию как точную до получения реального плана.

## 14. Этапы разработки

### V1 — UX prototype
- 2 слоя: Дом / Территория;
- этажи;
- архитектурная SVG/CSS-схема;
- hover/selection;
- камера zoom;
- карточка объекта;
- реальные проектные фотографии как временные media slots.

### V2 — spatial accuracy
- заменить схематическую геометрию на точный план после получения материалов;
- добавить двери/лестницы/балконы по реальному плану;
- уточнить mapping объектов каталога.

### V3 — live availability
- подключить существующую availability функцию;
- отображать реальные состояния;
- передавать выбранный объект в существующий booking flow.

### V4 — final media
- профессиональные фотографии;
- дополнительные фото;
- при необходимости видео/360°;
- финальная цветокоррекция и микровзаимодействия.

## 15. Критерий готовности

Пользователь должен за несколько секунд понять:

**«Это дом. Вот этажи. Вот где находятся комнаты. Я могу нажать на нужную комнату, приблизиться к ней, посмотреть её настоящую фотографию, понять условия и забронировать её.»**

При этом карта должна оставаться интересной для самостоятельного исследования: человек может не только искать номер, но и **играть с пространством FreeDom**.
