# FreeDom — метрики директора и правила решений

## Принцип
Метрика считается только при наличии определённого периода, знаменателя, источника и воспроизводимого расчёта. Нет данных — `NOT MEASURED`, а не ноль. Не выводить KPI из количества коммитов.

## Словарь метрик

| Переменная | Формула / способ | Источник |
|---|---|---|
| TASK_COMPLETION | завершённые / запланированные задачи × 100% | sprint/task register |
| TASK_ACCEPTANCE | принятые / завершённые задачи × 100% | acceptance log |
| FIRST_PASS_RATE | принятые с первой проверки / проверенные × 100% | QA log |
| REWORK_RATE | задачи с повторной реализацией / завершённые × 100% | issue/commit history |
| AVG_CYCLE_TIME | среднее время от start до acceptance | timestamps задач |
| BLOCKED_TIME | сумма времени в blocked | blocker log |
| WIP_COUNT | активные технические задачи в момент среза | sprint board |
| P0_COUNT…P3_COUNT | число открытых дефектов каждого приоритета | defect register |
| REGRESSION_RATE | новые регрессии / проверенные ранее исправленные сценарии × 100% | regression matrix |
| STATIC_QA_PASS | passed assertions / executed assertions | test log |
| BUILD_QA_PASS | статус сборки точного SHA | Vercel build |
| BROWSER_QA_PASS | passed browser cases / executed browser cases | browser report |
| SPEC_COMPLETENESS | заполненные обязательные поля / все обязательные поля | design spec checklist |
| SPEC_AMBIGUITY | количество открытых неоднозначностей до coding | clarification log |
| DESIGN_HANDOFF_SCORE | заполненные обязательные блоки передачи / обязательные блоки | design handoff |
| VISUAL_REFERENCE_COVERAGE | существенные UI задачи с референсом/скриншотом / все существенные UI задачи | task register |
| PLAN_ACCURACY | задачи, завершённые в согласованном scope / запланированные | sprint report |
| CHANGE_FAILURE_RATE | изменения, вызвавшие rollback/regression / все изменения | commit/defect log |
| IMPROVEMENT_IMPACT | разница выбранной метрики до/после внедрения метода | improvement experiment |

## KPI директора
- Delivery / принятый результат — 25%.
- QA и качество — 25%.
- Предотвращение регрессий — 20%.
- Скорость цикла — 15%.
- Координация и прозрачность — 15%.

Каждая категория оценивается по шкале 0–100 с заранее описанными критериями и доказательствами. Если входных данных нет, категория помечается NOT MEASURED; общий балл не рассчитывается. Не переносить старую оценку автоматически.

## Стартовые управленческие пороги
- Green: TASK_ACCEPTANCE ≥90%, нет новых P0/P1, REGRESSION_RATE ≤5% и все обязательные QA-gates выполнены. Допускается добавить одну небольшую задачу или увеличить объём на 10–15%.
- Amber: TASK_ACCEPTANCE 75–89% либо есть повторные переделки/рост блокировок. Объём не увеличивать; улучшить один узкий этап.
- Red: TASK_ACCEPTANCE <75%, новый P0/P1, REGRESSION_RATE >10% или критический сценарий не проверен. Приостановить расширение функциональности, стабилизировать.
- При отсутствии знаменателя/данных — статус UNKNOWN, не Green.

Пороги являются стартовыми гипотезами. После 2 полных циклов директор предлагает калибровку на основании статистики.

## Правила экспериментов над процессом
1. Назвать наблюдаемую проблему и baseline.
2. Выбрать не более 1–2 изменений процесса за цикл.
3. Указать ожидаемый эффект и метрику.
4. Сравнить сопоставимые циклы и объём задач.
5. Оставить метод только при доказанном улучшении без роста регрессий.
6. Зафиксировать решение в `PROCESS_IMPROVEMENTS.md`.

## Обязательные поля для каждой задачи
Task ID; роль; приоритет; дата/время начала; дата завершения; commit SHA; критерии приёмки; статус; число проверок; результат; переделки; блокировки; доказательство.

## Непереговорные QA правила
- Static ≠ build ≠ browser ≠ Android/network QA.
- READY Preview подтверждает сборку конкретного SHA, не внешний вид и не пользовательский сценарий.
- Нельзя присваивать PASS тесту, который не запускался.
- Любой P0/P1 блокирует увеличение нагрузки и Production GO.
