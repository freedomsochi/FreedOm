Они остаются важными сигналами, но не должны автоматически считаться подтверждённым текущим состоянием: текущая read-only проверка схемы Supabase не прошла из-за ошибки аутентификации read-only пользователя, а Security Advisor сообщил, что проект находится в hibernated состоянии. Поэтому SQL-изменения сейчас не выполнялись.

### Backend / интеграции
На подключённом Supabase project `vutmbhsclmcfqqlzxqkc` перечислены три активные Edge Functions:
- `create-public-booking` — ACTIVE, `verify_jwt=false`; использует service-role только внутри серверной функции и вызывает RPC `create_public_booking`.
- `public-availability` — ACTIVE, `verify_jwt=false`; использует anon key и RPC `get_public_room_availability`.
- `telegram-notify` — ACTIVE, `verify_jwt=true`; отправка уведомления вызывается из booking function с серверным service-role bearer.

Публичный JWT-off режим первых двух функций сам по себе не является дефектом: это публичные пользовательские сценарии. Нужны ограничения частоты/антиспам и проверка серверных RPC, а не механическое включение JWT.

### Найденная и исправленная проблема клиентского кода
В `profile.html` ошибки Supabase и исключения вставлялись в DOM через `innerHTML`. Сообщения ошибок являются динамическими данными, поэтому такой способ создаёт ненужную HTML injection поверхность.

Исправлено в отдельном коммите:
- добавлен `showLoadingError()`;
- сообщения теперь вставляются через `textContent`;
- все три динамических вывода ошибок через `loadingState.innerHTML` удалены.

### P1 — проверка критических пользовательских сценариев
**Ответственный:** тестировщик; **поддержка:** технический программист.
- Регистрация / вход / выход / профиль.
- Проверка доступности комнат → отправка заявки → серверная перепроверка → уведомление.
- Административное подтверждение и отмена бронирования.
- События → регистрация → карточка гостя → финансовая детализация.
- Заказ кухни и обработка результата.
- Проверить двойное нажатие, повторную отправку, ошибки сети, истёкшую сессию и пустые данные.
- Ни при каких условиях не отправлять реальные заказы, брони и оплаты в production ради теста.
